# 架构

三个组件，一条主循环。

## 组件

```
┌──────────────────────────────────────────────────────────┐
│ scheduler（外部）                                         │
│   一次性任务：到了时刻，投递一段提示词                    │
└───────────────┬──────────────────────────────────────────┘
                │ 触发
                ▼
┌──────────────────────────────────────────────────────────┐
│ agent 回合                                                │
│  0. watch_documents.py   → 有没有新文件                   │
│  1. 读新文件 / 检索 recall.py                             │
│  2. 干活：回话、写 documents/、更新 memory/state.md        │
│  3. biorhythm_clock.py --json --regen → 下一次时刻         │
│  4. 挂新任务（恰好一条 pending）                          │
└──────────────────────────────────────────────────────────┘
```

## 数据流

| 文件 | 写入者 | 读者 | 生命周期 |
|---|---|---|---|
| `clock/.clock_state.json` | 时钟脚本 | 时钟脚本 | 覆盖 |
| `clock/.documents_index.json` | 哨兵 | 哨兵 | 覆盖 |
| `documents/*` | agent / 用户 | agent | 追加 |
| `memory/state.md` | agent | agent | 覆盖 |
| `memory/rapport.md` | agent | agent | 追加 |
| `memory/session/*` | 运行时 | recall.py | 只读 |

## 不变量

1. **任意时刻恰好一条时钟任务 pending**。0 条＝漏排，2 条＝重复。
2. 时钟任务的时刻必须等于 `--json` 输出的 `next`；对不上就重抽，不手改。
3. `documents/` 里只放有出处的文件；模型自造的内容要标明是自造。
4. `state.md` 每次整篇覆盖，不追加；超过 50 行说明该删了。
5. 摘要只能由人（或模型在明确"这是摘要"的前提下）写，脚本不自动生成。

## 失败模式

| 现象 | 原因 | 处理 |
|---|---|---|
| 两条时钟任务 | 重挂前没删旧的 | 删旧留新，跑一次校验 |
| 时刻漂移 | 用了相对时间（`after_seconds`） | 改用绝对时刻 |
| 触发时不读文件 | 提示词没写第 0 步 | 改提示词模板，或让调度器带摘要 |
| 检索命中一堆系统消息 | 存档里混入提示词快照 | `recall.py` 的 `is_meta()` 过滤 |
| 记忆越写越长 | 把 state 当日记 | 只写现状，过程交给存档 |
