# 记忆：四层，别让摘要替你记事

长对话里最先坏掉的不是上下文长度，是**确定性**。压缩一次，细节从"他说过"变成"大概说过"；再压一次，就变成"我记得是这样"。三层之后，模型开始用合理的措辞补记忆里的洞。

所以：**能查原文的，不靠摘要；需要摘要的，标清是摘要。**

## 四层

| 层 | 文件 | 内容 | 更新方式 | 谁读 |
|---|---|---|---|---|
| 现场 | `memory/state.md` | 时间、地点、刚发生什么、关系温度、未闭合的线索 | 整篇覆盖 | 每次开工第一件事 |
| 关系 | `memory/rapport.md` | 对方是什么人、怎么待他、什么话别说 | 只追加 | 需要调整语气时 |
| 事实 | `documents/` | 真实的文件、字条、稿子 | 追加，带出处 | 讲事实前 |
| 存档 | `memory/session/` | 原始事件日志 | 运行时写 | 用 `recall.py` 按需检索 |

四层的分工是：**state 说"现在"，rapport 说"怎么处"，documents 说"什么是真的"，session 说"原话是什么"。**

## state.md 怎么写

- 50 行以内。超了就是写了过程，删。
- 只写**现状**：现在几点、在哪、最近一件大事、哪几条线没闭合。
- 线索用 `[open]` / `[closed]` 标，关闭的留着，别删——"查过但没有"本身是信息。
- 每次整篇重写，不在末尾追加。覆盖是刻意的：逼你只留还活着的部分。

## rapport.md 怎么写

- 只记**怎么对待**，不记做过什么。做过的事在 documents 和存档里。
- 一条一行，写触发条件："他夸完就走，别追着要结论"。
- 允许写"记不清"。不确定的口气比确定的错误便宜。

## 精度分级

每条记忆都该带一个精度，虽然不必写出来：

| 精度 | 例子 | 用法 |
|---|---|---|
| 原话 | 存档里能搜到的句子 | 可以引用 |
| 转述 | 你当时写的摘要 | 可以说"大意是"，不能说"他说" |
| 推断 | 你从语气里猜的 | 不许当成事实讲 |
| 空白 | 没记 | 说"记不清"，或者去查 |

把空白填成推断，是记忆系统最常见的谎。

## 检索，不总结

```bash
python tools/recall.py 关键词 --window 2 --limit 3
```

它只做两件事：找到包含关键词的消息，显示前后各 `window` 条。**不做摘要、不做归纳、不生成"他大概意思是"。**

原因很实际：摘要是一次有损压缩，而且损失的位置由模型决定。检索不损失，只是慢一点。

`recall.py` 默认跳过系统注入的消息（提示词快照、运行时上下文、调度通知），否则一搜关键词全是这些。

## 为什么不自动写摘要

自动摘要会让"不确定"悄悄变成"确定"：模型把模糊的印象写成通顺的句子，下一次读到的就是那个句子，而不是原始事实。三轮之后，没人分得清哪句是发生过的事。

所以脚本只归档、只检索，不总结。总结留给人，或者留给明确说了"以下是摘要"的回合。

## 反模式

- 把 `state.md` 写成日记。→ 只留现状。
- 在 `documents/` 里放模型编的文件。→ 编的要标明是编的。
- 用摘要代替原文去引用。→ 引用必须能落到存档。
- 每次开工把 `transcript.md` 整个读进来。→ 那是检索源，不是上下文。
